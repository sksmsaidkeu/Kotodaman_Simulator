# 코토테스터 배경 장식: 배치 화면

창 배경(`Bg.Backdrop`)에 구름·물결·ことだま 히라가나 같은 **범용 장식 모티프**를 반투명으로 얹는다. [[PRD_UI.md]] §2가 "캐릭터 일러스트·SD 스프라이트는 저작물이라 가져오지 않는다"고 이미 못박아 둔 것과 같은 원칙 — 이 PRD는 모티프의 그림 자체가 아니라 **어디에 놓을 수 있는가**만 다룬다.

| 항목 | 내용 |
|---|---|
| 대상 | KotodamanWordFinder (WPF/.NET 8), UI 리디자인(P1~P9) 완료 이후 |
| 참조 자료 | `Kotodaman_UI_1.jpg` 강림 목록 카드 (캐릭터 자체는 미사용, 배치 감각만 참고) |
| 기능 변경 | 없음. 순수 프레젠테이션 레이어 |
| 신규 의존성 | 0개 (벡터 Path로만, PRD_UI와 동일 방침) |

---

## 1. 지금 상태 (측정치)

`Bg.Backdrop` 토큰이 실제로 화면에서 차지하는 면적을 창별로 재봤다. **결과: 어느 창도 배경이 넓게 비어 있지 않다.**

- **MainWindow** — 루트가 `ScrollViewer > StackPanel Margin="20"`. 안쪽은 `Bg.Panel` 카드(둥근 모서리)가 촘촘히 쌓여 있어, `Bg.Backdrop`이 보이는 곳은 **창 가장자리 20px 여백 + 카드 사이 틈(8~14px)뿐**이다.
- **다이얼로그 7개** — `ModalCardWindowStyle`(`Themes/Controls.xaml:215`)이 공용 템플릿. 창 자체가 `AllowsTransparency=True` + `Background=Transparent`이고, `CardShadow` 보더 하나가 `Bg.Backdrop` 색으로 카드 전체를 채운다. 그 위에 제목 행(**Row 0, 높이 58, 전체 폭**)만 자체 패널이 없어 `Bg.Backdrop`이 그대로 드러나고, 본문 행(Row 2)은 각 창의 `Bg.Panel`/`Bg.Field` 섹션이 다시 촘촘히 덮는다.

**함정 — `Bg.Backdrop`은 "창 배경" 전용 토큰이 아니다.** 같은 키가 `CharacterWebImportWindow`의 64×48 썸네일 플레이스홀더, `DeckScreenshotImportWindow`의 목록 행 배경 등 **작은 UI 부품 채움색**으로도 8곳에서 재사용되고 있다(`grep Bg.Backdrop` 실측). 장식을 토큰(브러시) 자체에 이미지로 얹으면 이 부품들에도 전부 새어 들어간다 — PRD_UI가 겪은 "색은 hex로만 안 흐른다" 함정과 같은 종류다. **장식은 토큰이 아니라 창 루트의 별도 레이어(각 창 XAML에 Canvas/Grid 한 겹 추가)로 넣어야 한다.**

## 2. 배치 후보 비교

| # | 후보 | 노출 면적 | 손대는 파일 | 비고 |
|---|---|---|---|---|
| A | **MainWindow 여백** — 20px 창 테두리 + 카드 사이 틈 | 좁음, 그러나 사용자가 가장 오래 보는 화면 | `MainWindow.xaml` 1개(bespoke, 공유 스타일 없음) | 창 크기를 늘려도 `StackPanel`이 그대로 늘어나 여백이 넓어지지 않음(확인함) |
| B | **다이얼로그 공용 타이틀 행** — 58px, 전체 폭, 7개 창 전부 | 창마다 얇지만 **7개 동시 적용** | `Themes/Controls.xaml`의 `ModalCardWindowStyle` **1곳만** | P8 경고 배너·P1 카드 모달과 같은 "공용 템플릿 1곳 수정 → 다수 창 반영" 패턴. 레버리지 제일 큼 |
| C | **다이얼로그 본문 행 틈** | 창마다 다름, 사실상 거의 없음(섹션이 이미 꽉 채움) | 7개 창 각각 개별 조사 필요 | 비용 대비 노출 면적이 안 나옴. PRD_UI의 "롱테일 147색" 같은 함정 — 보류 |
| D | A + B | 위 둘 합 | 2곳 | — |

## 3. 권장안

**B(다이얼로그 타이틀 행)를 먼저, A(MainWindow 여백)를 다음으로.** 이유:

- B는 파일 1개(`Controls.xaml`)만 고치면 7개 창에 동시 반영된다 — PRD_UI가 이미 검증한 "공용 스타일 1곳" 레버리지와 동일 구조라 리스크가 알려져 있다.
- A는 파일 1개뿐이지만 공유 스타일이 없어 재사용 레버리지가 없다. 대신 MainWindow는 앱의 얼굴이라 우선순위가 있다.
- C는 배제. 노출 면적 대비 조사 비용이 안 맞는다.

## 4. 범위 밖 (다음 PRD)

- 모티프 자체(구름/물결/ことだま 글자)의 형태·배치 밀도·색 토큰 — 이 PRD는 "어디"만 다룬다.
- 라이트/크림 팔레트에서의 불투명도 값 — `check_contrast.py` 대비 재검증 필요, 별도 단계.

## 5. 결정 필요

- **D-1** B만 먼저 갈지, B+A(D안)로 한 번에 갈지.
- **D-2** A를 하더라도 지금 여백(20px)을 넓힐지(레이아웃 변경 필요) 그대로 20px 안에서만 장식할지 — 넓히면 리스트/그리드가 좁아지는 트레이드오프 발생.
