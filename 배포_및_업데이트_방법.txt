코토다망 최장 단어 탐색기 v1.25.1 배포 및 업데이트 구조

1. 코드·UI·기능을 수정한 경우
- 개발 폴더에서 clean_run.bat으로 먼저 테스트합니다.
- 데이터 변경이 있다면 먼저 데이터 업데이트를 생성·검수하고 accept_data_baseline.bat으로 승인합니다.
- 버전 번호를 올린 뒤 publish_release.bat을 실행합니다.
- 승인되지 않은 characters.json 또는 이미지 변경이 남아 있으면 Publish가 중단되어 실수로 섞이지 않습니다.
- Publish 폴더에는 최종 portable.zip만 남습니다.
- 압축 전 300~400MB 폴더와 bin/obj는 자동 삭제됩니다.
- 다른 사용자에게는 portable.zip만 전달합니다.

2. 캐릭터·이미지만 수정한 경우
- 프로그램에서 캐릭터를 추가하거나 수정합니다.
- create_data_update.bat을 실행하고 새 데이터 버전을 입력합니다.
  예: 2026.08.20.1
- Updates 폴더에 이전 공식 기준과의 차이만 담긴 ZIP이 생성됩니다.
- 이 경우 전체 프로그램 Publish를 다시 만들 필요가 없습니다.

3. 데이터 업데이트 적용 방법
- 프로그램을 완전히 종료합니다.
- 데이터 업데이트 ZIP을 apply_data_update.bat 위로 끌어다 놓습니다.
- 적용 전에 사용자 Data 전체 백업 ZIP이 자동 생성됩니다.
- 신규 캐릭터는 추가되고, 공식 수정은 기존 사용자 수정과 3-way merge됩니다.
- 같은 필드를 사용자가 따로 수정했다면 사용자 값이 우선 보존됩니다.

4. 공식 데이터 기준 확정
- 생성한 데이터 업데이트 ZIP을 직접 테스트합니다.
- 실제 배포까지 끝난 뒤에만 accept_data_baseline.bat을 실행합니다.
- 그러면 현재 Data가 다음 데이터 업데이트의 비교 기준이 되고, 생성한 패치가 Data\BundledUpdates에 보관됩니다.
- 이후 전체 프로그램 업데이트를 받은 기존 사용자는 자신의 데이터 버전에 맞는 내장 패치를 시작 시 자동 적용합니다.
- ZIP을 만들자마자 기준을 확정하면 재생성이 어려워지므로 주의합니다.

5. 개발 폴더 정리
- clean_workspace.bat은 bin, obj, Publish의 압축 해제 폴더를 삭제합니다.
- Publish 안의 portable.zip은 삭제하지 않습니다.
- Data, 소스 코드, ReleaseTools/Baseline, 사용자 LocalAppData는 건드리지 않습니다.

6. 저장 위치
- 개발용 공식 기본 데이터: 개발 폴더\Data
- 사용자 실제 수정 데이터: %LocalAppData%\KotodamanWordFinder\Data
- 전체 프로그램 배포 ZIP: 개발 폴더\Publish
- 데이터 업데이트 ZIP: 개발 폴더\Updates
- 데이터 비교 기준: 개발 폴더\ReleaseTools\Baseline
- 자동 백업: %LocalAppData%\KotodamanWordFinder\Backups

현재 권장 흐름
- UI 논의 중: clean_run.bat으로 개발 및 테스트
- UI 확정 후 코드 변경 배포: publish_release.bat
- 배포 후 새 캐릭터만 추가: create_data_update.bat
